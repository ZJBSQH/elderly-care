P0 权限优化知识总结

1. userId 和 elderId 不能混用

userId 是认证服务中的账号 ID，elderId 是用户服务中的老人档案 ID。 二者可能刚好相同，但不能依赖这种巧合。业务服务如果需要老人档案 ID，应通过用户服务查询真实的 elder.id。

2. JWT 不只保存登录状态，也可以承载基础角色信息

本项目在 JWT 中保存 userType，服务内过滤器解析后转换为 ROLE_ELDER、ROLE_FAMILY、ROLE_ADMIN。 这样后台接口可以直接校验管理员角色。

3. 数据权限应放在数据归属服务中判断

老人和家属绑定关系属于 user 服务，因此 health、medicine、remind 服务不应该自己猜权限， 而是通过 Feign 调用 user 服务的权限接口，判断当前登录用户是否能访问某个 elderId。

4. 公开接口和个性化接口要分开

AI 健康知识问答可以不登录，因为它只使用公共知识库；个性化 RAG 和用药建议必须登录， 因为它会读取个人用药、提醒等隐私数据。

5. 面试表达

我把权限分成两层：第一层是认证，网关和服务内过滤器校验 JWT；第二层是业务数据权限， 由 user 服务统一判断老人本人、绑定家属、管理员三种访问场景。这样可以避免各业务服务重复维护绑定规则。
